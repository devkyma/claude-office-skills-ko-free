# 폴더 정리 (file-organizer-ko)

폴더 정리가 미뤄지는 이유는 귀찮아서가 아니라 무서워서다. 옮기다가 파일을 잃어버리거나, 어디로 갔는지 모르게 되거나, 같은 이름끼리 덮어쓸까 봐다. 이 스킬은 그 두려움을 세 가지 장치로 없앤다. 옮기기 전에 계획표를 보여주고, 옮긴 기록을 undo.json으로 남겨 한 번에 되돌릴 수 있게 하며, 어떤 경우에도 파일을 삭제하거나 덮어쓰지 않는다. 그래서 "일단 해 보고 마음에 안 들면 되돌리기"가 가능하다.

## 작업 순서

1. **대상 폴더를 확정한다.** 사용자가 말한 폴더의 절대 경로를 정한다(`~/Downloads`, `~/Desktop`, 한국어 macOS는 `~/Downloads`가 Finder에서 "다운로드"로 보인다). 홈 폴더 전체나 루트, 시스템 폴더는 스크립트가 거부한다. 폴더 바로 아래 파일만 대상이고 하위 폴더는 건드리지 않는다. 하위 폴더까지 원하면 폴더별로 따로 실행한다.
2. **계획을 만든다(dry-run).** 아무것도 옮기지 않고 표와 `moves.json`을 만든다.
   ```
   python3 scripts/plan_moves.py ~/Downloads
   python3 scripts/plan_moves.py ~/Downloads --by-year            # 문서/2026/ 식 연도 하위 폴더
   python3 scripts/plan_moves.py ~/Downloads --by-year --rename   # 파일명 YYYYMMDD_문서명 정규화까지 계획에 포함
   python3 scripts/plan_moves.py ~/Downloads --rule "음성:mp3,wav,m4a"   # 규칙 추가
   ```
   파이썬 실행 파일은 `~/.claude/office-venv/bin/python`(Windows: `%USERPROFILE%\.claude\office-venv\Scripts\python.exe`)이 있으면 그것을 쓰고, 없으면 `python3`를 쓴다. 패키지 오류가 나면 설치 스크립트(install.sh / install.ps1)를 다시 실행하라고 안내한다. 이 스킬의 스크립트는 표준 라이브러리만 쓴다.
3. **계획표를 사용자에게 보여주고 한 번만 묻는다.** 파일이 30개를 넘으면 전체 표 대신 카테고리별 건수와 "기타"로 분류된 파일 목록, 이름이 바뀌는 파일 목록만 보여준다. 물을 것은 최대 3개로 묶는다: (1) 이 분류대로 옮겨도 되는지, (2) 연도 폴더·이름 정규화를 쓸지, (3) 기타로 분류된 파일을 어디로 보낼지. 바탕화면·다운로드 폴더면 반드시 명시적인 "적용", "옮겨줘", "진행" 같은 답을 받는다. "응 알아서"는 승인이 아니므로 다시 확인한다.
4. **규칙을 조정해 다시 계획한다.** 사용자가 "영수증은 경비/로", "PSD는 디자인 폴더로"라고 하면 `--rule "디자인:psd,ai"`처럼 규칙을 추가하거나 `moves.json`의 `dst`를 직접 고쳐서 계획을 다시 보여준다. `moves.json`을 손으로 고쳤으면 그 파일로 적용한다.
5. **적용한다.** 승인 받은 뒤에만 실행한다. 이름 충돌은 `_2`, `_3`으로 피하고, 결과는 `undo.json`과 `정리_로그_날짜.txt`에 남는다.
   ```
   python3 scripts/apply_moves.py moves.json          # 검증만(원본 존재·충돌 예고)
   python3 scripts/apply_moves.py moves.json --apply  # 실제 이동
   ```
6. **결과를 보고하고 되돌리는 법을 알려준다.** 카테고리별 이동 건수, 충돌로 이름이 바뀐 파일, 건너뛴 파일(진행 중 다운로드·잠금 파일)을 요약하고, 되돌리기 명령을 한 줄 남긴다: `python3 scripts/undo_moves.py undo.json --apply`.

## 출력 형식

계획 단계에서 사용자에게 보여주는 형식이다. 스크립트 표를 그대로 붙이되 30개가 넘으면 요약형으로 바꾼다.

```
## 정리 계획: ~/Downloads (파일 24개, 건너뜀 5개) — 아직 옮기지 않았습니다

| 폴더 | 건수 | 예시 |
|---|---|---|
| 문서/계약/2026 | 3 | 20260915_고객사A_용역계약서_v2.pdf, NDA_draft_final_final.docx |
| 문서/2026 | 6 | 주간보고_9월3주.pptx, 견적서_마바사_2026-09-22.xlsx |
| 이미지/스크린샷/2026 | 2 | 스크린샷 2026-09-28 오후 3.12.45.png |

확인 부탁드립니다: ① 이대로 옮길까요? ② 기타 3개는 어디로 보낼까요? ③ 파일명 정규화도 적용할까요?
```

적용 후 보고:
```

되돌리기: python3 scripts/undo_moves.py undo.json --apply
로그: 정리_로그_20261001_093012.txt
```

## 작성 원칙과 이유

- **계획 없이 옮기지 않는다.** 사용자는 자기 폴더에 무엇이 있는지 스스로도 잘 모른다. 표를 보고 나서야 "아, 그건 옮기면 안 되는데"가 나온다. 그래서 dry-run이 기본이고 `--apply`는 사용자의 승인 뒤에만 붙인다.
- **삭제하지 않는다.** 중복으로 보이는 파일, 0바이트 파일, 오래된 설치 파일도 옮기기만 한다. "지워도 될 것 같은 파일" 목록은 만들어 줄 수 있지만 삭제는 사용자가 직접 한다. 되돌릴 수 없는 작업은 스킬의 몫이 아니다.
- **덮어쓰지 않는다.** 이름이 같으면 `_2`를 붙인다. 내용이 같아 보여도 마찬가지다. 같은지 판단하는 건 사용자다.
- **되돌릴 수 있게 남긴다.** undo.json은 실제로 옮겨진 경로(충돌로 바뀐 이름 포함)를 기록한다. 되돌리기도 dry-run이 기본이다.
- **진행 중인 것은 건드리지 않는다.** `.crdownload`, `.part`, `.download`, `~$` 잠금 파일은 옮기면 다운로드·편집이 깨진다. 숨김 파일과 하위 폴더도 건드리지 않는다.
- **분류는 단순하게, 예외는 규칙으로.** 기본 6개 폴더면 대부분 충분하다. 사용자의 업무 특성(디자인·회계·개발)은 `--rule`로 얹는다. 폴더가 12개 넘게 생기면 정리가 아니라 새로운 혼란이다.
- **이름 정규화는 계획에서만 보여준다.** 파일명이 바뀌면 다른 곳의 링크·참조가 끊길 수 있다. `--rename`은 계획표에서 새 이름을 보여주고 사용자가 확인한 뒤에만 적용한다.

## 상황별 처리

- **다운로드·바탕화면 폴더**: 스크립트가 경고를 출력한다. 계획을 보여주고 명시적 승인을 받는다. 바탕화면은 사용자가 "지금 쓰는 파일"을 올려둔 곳이므로 최근 3일 안에 수정된 파일은 계획에서 빼자고 먼저 제안한다(`moves.json`에서 해당 항목 삭제).
- **프로젝트 폴더(문서 종류가 한 가지)**: 확장자 분류가 의미 없다. `--by-year`나 파일명 키워드(계약·견적·회의·보고) 하위 폴더 중심으로 계획하고, 필요하면 `--rule "고객사A:..."`처럼 사용자가 준 기준을 규칙으로 바꾼다.
- **기타로 많이 분류될 때**: 확장자가 없거나 낯선 확장자다. 파일 목록을 보여주고 어디로 보낼지 묻는다. 모르는 확장자는 옮기지 않는 것이 안전하다(`moves.json`에서 제거).
- **이미 일부 정리된 폴더**: 기존 `문서/` 같은 폴더가 있으면 그 안에 합쳐진다. 폴더 이름이 다르면(`Documents/`) 사용자에게 어느 쪽 이름을 쓸지 묻고 `--rule`로 맞춘다.
- **외장 드라이브·네트워크 드라이브**: 이동이 느리고 중간에 끊길 수 있다. 100개 단위로 `moves.json`을 나눠 적용하자고 제안한다.
- **되돌리기 요청**: `undo.json`을 찾아 dry-run으로 목록을 보여준 뒤 `--apply`. 되돌린 뒤 남는 빈 폴더는 지우지 않고 목록만 알려준다.

## 변형 요청

- **연도·월별 정리**: `--by-year`가 기본. 월별까지 원하면 계획 후 `moves.json`의 `dst`를 `문서/2026/09/`처럼 고쳐 적용한다.
- **파일명 규칙 통일**: `--rename`으로 `YYYYMMDD_문서명.확장자`. 날짜는 파일명에 있으면 그것을, 없으면 수정일을 쓴다는 점을 사용자에게 알린다.
- **보고서용 폴더 현황표**: 옮기지 않고 `plan_moves.py` 표만 사용해 종류별 건수·용량 요약을 만든다.
- **중복 후보 목록**: 이름이 `(1)`, `copy`, `사본`으로 끝나는 파일과 원본 후보를 표로 보여준다. 삭제는 하지 않는다.
- **정리 규칙 저장**: 사용자가 정한 `--rule` 조합을 명령 한 줄로 정리해 주어 다음에도 같은 규칙을 쓰게 한다.

## 예시

**입력**: "다운로드 폴더 좀 정리해줘. 연도별로."

**실행**: `python3 scripts/plan_moves.py ~/Downloads --by-year` → 계획표를 보여주고 "기타 3개(noname, data.json, Untitled.key)는 어디로 보낼까요? 나머지는 이대로 옮길까요?"라고 한 번 묻는다.

**사용자**: "기타는 놔두고 나머지 적용."

**실행**: `moves.json`에서 기타 3건을 제거 → `python3 scripts/apply_moves.py moves.json --apply`

**출력**:
```
정리 완료: 21개 이동, 이름 충돌 1건(계약서 초안 (1).docx → 문서/계약/2026/계약서 초안 (1)_2.docx), 건너뜀 5개(진행 중 다운로드 2, 잠금 파일 1, 숨김 1, 하위 폴더 1)
남겨둔 파일: noname, data.json, Untitled.key
되돌리기: python3 scripts/undo_moves.py undo.json --apply
```

## 마무리 점검

- 계획표를 보여주고 명시적 승인을 받은 뒤에 `--apply`를 실행했는가?
- 삭제·덮어쓰기가 한 건도 없는가? 충돌은 `_2`로 처리됐는가?
- undo.json 경로와 되돌리기 명령을 사용자에게 알려줬는가?
- 진행 중 다운로드·잠금 파일·숨김 파일·하위 폴더를 건너뛰었는가?
- 기타로 분류된 파일을 사용자 확인 없이 옮기지 않았는가?
- 이름 정규화가 사용자 확인 없이 적용되지 않았는가?
- 폴더가 너무 잘게 쪼개지지(12개 이상) 않았는가?
