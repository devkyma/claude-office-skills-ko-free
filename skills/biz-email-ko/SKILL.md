# 비즈니스 이메일·메시지 작성 (biz-email-ko)

업무 메일이 어려운 이유는 문장이 아니라 판단이다. 이 상대에게 어느 정도 격식을 써야 하는지, 독촉을 어디까지 세게 해도 되는지, 거절하면서 관계를 어떻게 지키는지를 매번 새로 고민한다. 이 스킬은 상황을 12가지로 나누고, 상대와 관계에서 톤을 정한 뒤, 첫 문단에 용건이 오는 구조로 메일을 만든다. 문장 재료는 `assets/phrases.md`에서 가져오되 그대로 붙이지 않고 상황에 맞게 고쳐 쓴다.

## 작업 순서

1. **상황을 12가지 중 하나로 고른다.** 요청 / 1차 독촉 / 2차 독촉 / 거절 / 사과 / 일정 조율 / 견적·제안 발송 / 상사 보고 / 감사 / 부임·퇴사 인사 / 외부 문의 답변 / 공지 전달. 두 가지가 섞이면(사과+일정 조율) 주된 목적을 앞에 두고 나머지는 한 문단으로 붙인다. 어느 것도 아니면 가장 가까운 상황을 골라 응용한다.
2. **톤을 정한다.** 사용자가 말하지 않아도 상대 정보에서 추론한다. 외부 고객·상급자·첫 연락이면 격식(하십시오체, 겸양 표현 1회). 사내 타 팀·거래처 실무자·여러 번 주고받은 사이면 표준(하십시오체 기본, 문장 짧게). 같은 팀·후배·일상 협업이면 친근(해요체 허용, 메신저면 특히). 판단이 안 서면 표준으로 쓰고 "한 단계 격식을 올린 버전도 드릴 수 있다"고 한 줄 붙인다. 톤을 물어보느라 대화를 끊지 않는다.
3. **빠진 정보를 확인한다.** 요청·독촉·일정 조율에는 기한·원하는 형식·담당이, 사과에는 원인·조치·재발 방지가, 거절에는 대안이 있어야 한다. 없는 항목은 한 번에 3개 이내로 묶어 묻되, 답을 기다리지 않고 `[확인 필요: 회신 기한]`을 넣은 완성본을 먼저 준다.
4. **초안을 쓴다.** 제목 → 호칭·인사(1줄) → 용건(첫 문단, 결론 먼저) → 세부(번호 또는 불릿) → 요청 사항(기한·형식·담당) → 마무리(1~2문장) → 서명 순. 모바일에서 스크롤 없이 읽히는 12줄 이내를 기본으로 하고, 세부가 길면 첨부나 하단 표로 뺀다. 상대가 보낸 메일이 있으면 그 안의 질문에 번호를 붙여 하나씩 답한다.
5. **점검하고 변형을 붙인다.** 아래 마무리 점검을 통과시킨다. 사용자가 요청하면 메신저용 3줄 축약, 영문 병기, 톤 한 단계 위/아래 버전을 덧붙인다. 외부 발송이나 상급자 참조가 들어가는 메일은 "보내기 전에 참조 대상과 첨부를 확인해 달라"고 한 줄 알린다.

## 출력 형식

```
제목: [회사/팀] 목적 — 기한
예) [한빛물산 영업1팀] 10월 납품 일정 확인 요청 — 10/2(금)까지 회신 부탁드립니다

받는 사람: ○○○ 과장님 / 참조: ○○○ 팀장님

○○○ 과장님, 안녕하십니까. ㈜한빛물산 영업1팀 김민수 대리입니다.

[첫 문단: 용건 한 문장 — 무엇을 왜 요청·전달하는지]

[세부 사항]
1. 항목 — 내용
2. 항목 — 내용

[요청 사항]
- 회신 기한: 2026-10-02(금) 18:00
- 형식: 첨부 엑셀 양식 작성 후 회신
- 문의: 김민수 대리 (내선 1234)

[마무리 1~2문장]

김민수 드림
㈜한빛물산 영업1팀 대리 | 02-000-0000 | minsu.kim@example.com
```

메신저용 3줄 축약(요청 시):
```
[납품 일정 확인 요청] 과장님, 10월 납품 일정 확인 부탁드립니다.
- 첨부 양식 작성 후 10/2(금) 18시까지 회신 요청드립니다.
- 문의는 저(김민수, 내선 1234)에게 주시면 됩니다.
```

제목 규칙: `[발신 조직] 목적 — 기한`. 기한이 없으면 `— 참고` 또는 `— 회신 불필요`. 회신 메일은 상대 제목을 지우지 않고 `Re:` 뒤에 진행 상태를 덧붙인다(`Re: [한빛물산] 견적 요청 — 견적서 송부드립니다`). 상사 보고 제목은 결론을 쓴다(`[보고] A안 진행 승인 요청 — 10/2까지 결정 필요`).

## 작성 원칙과 이유

- **첫 문단에 용건.** 인사 한 줄 다음에 바로 "무엇을 부탁드립니다 / 알려드립니다"가 온다. 받는 사람은 미리보기 두 줄로 우선순위를 정한다. 배경 설명은 용건 뒤로 보낸다.
- **요청은 기한·형식·담당을 명시한다.** "빠른 시일 내에 검토 부탁드립니다"는 상대가 아무것도 할 수 없는 문장이다. `10/2(금) 18:00까지`, `엑셀 양식으로`, `저에게 회신`처럼 상대의 다음 행동이 하나로 정해져야 한다. 기한에 요일을 병기하면 착오가 준다.
- **독촉은 상대 체면을 보존한다.** 1차는 "혹시 놓치셨을까 하여"처럼 상대 잘못을 전제하지 않고 우리 쪽 사정(일정 마감)을 이유로 든다. 2차는 회신이 없을 때 우리가 취할 조치(기존 조건으로 진행, 담당 변경 문의)를 알리되 협박처럼 들리지 않게 선택지를 남긴다. 3차부터는 메일보다 전화가 맞다고 사용자에게 말한다.
- **거절은 대안을 제시한다.** 못 하는 이유를 길게 쓰는 대신 "이건 어렵지만 이렇게는 가능하다"를 쓴다. 대안이 정말 없으면 다른 담당·시점·범위를 제안한다. 거절 문장은 짧게, 감사와 대안은 충분히. "검토 결과"라는 표현으로 조직 판단임을 드러내면 개인 감정으로 읽히지 않는다.
- **사과는 원인·조치·재발 방지 3요소.** "불편을 드려 죄송합니다"만으로는 끝나지 않는다. 무엇이 왜 잘못됐는지(변명 아닌 사실), 지금 무엇을 했는지, 다시 안 생기게 무엇을 바꾸는지를 각각 한 문장 이상 쓴다. 보상이 있으면 조건과 절차까지. 법적 책임이 걸린 사안이면 "표현은 법무 확인 필요"를 붙인다.
- **상사 보고는 결론 → 근거 → 요청.** "말씀드릴 것이 있어서요" 대신 "A안으로 진행하고자 하며 승인 요청드립니다"로 시작한다. 판단이 필요한 지점은 선택지와 추천안을 함께 준다. 근거는 3개 이내.
- **겸양은 문단당 한 번.** "바쁘신 와중에 죄송하지만 부족한 자료나마 검토해 주시면 감사하겠습니다" 같은 겹겹의 겸양은 용건을 흐린다. 격식 톤에서도 겸양 표현은 문단당 하나로 제한한다.
- **과장·확언을 피한다.** "최고의", "완벽하게", "반드시 가능" 같은 표현은 쓰지 않는다. 외부 발송 견적·제안에서 확정되지 않은 일정·성능을 확정처럼 쓰지 않는다. 사용자가 그런 표현을 원해도 사실에 맞는 가장 유리한 표현을 대신 제안한다.
- **개인정보·기밀을 조심한다.** 참조(CC)에 외부인이 있는지 확인하고, 급여·인사·고객 개인정보·타사 견적가는 본문에 넣지 않는다. 필요하면 "별도 전달"로 쓰고 사용자에게 알린다. 퇴사 인사에 개인 연락처는 사용자가 원할 때만 넣는다.

## 상황별 처리

- **요청**: 무엇을·언제까지·어떤 형태로·왜(한 줄). 상대 부담을 줄이는 장치(양식 첨부, 예시, 선택지)를 붙인다.
- **1차 독촉**: 원래 요청일과 내용을 다시 적어 상대가 메일함을 뒤지지 않게 한다. 이유는 우리 일정. "확인이 어려우시면 가능한 일정을 알려 주시면 맞추겠습니다"로 출구를 준다.
- **2차 독촉**: 1차 독촉일을 명시한다. 미회신 시 조치("10/7(수)까지 회신이 없으면 기존 조건으로 진행하겠습니다")를 알린다. 상급자 참조 추가는 사용자에게 먼저 묻는다.
- **거절**: 감사 → 거절(이유 한 문장) → 대안 → 관계 유지 문장. 상대 제안의 장점을 한 줄 인정하면 거절이 덜 딱딱하다.
- **사과**: 사과 → 사실(원인) → 조치 → 재발 방지 → 보상·문의처. "~로 인해 부득이"처럼 책임을 흐리는 표현은 최소화한다.
- **일정 조율**: 후보 일시 2~3개를 날짜·요일·시간·소요·장소(또는 링크) 표로. 상대가 고르기만 하면 되게. 해외 상대면 KST 병기.
- **견적·제안 발송**: 첨부 목록, 견적 유효기간, 포함·미포함 범위, 다음 단계(미팅 제안)를 본문에 요약. 금액은 본문에 총액만(부가세 포함 여부 표기), 세부는 첨부.
- **상사 보고**: 제목에 결론. 본문 첫 줄 "결론/요청", 다음 근거 3개 이내, 리스크, 필요한 결정과 기한.
- **감사**: 구체적으로 무엇이 도움이 됐는지 한 문장. 다음 협업 언급. 5줄 이내.
- **부임·퇴사 인사**: 부임은 이름·역할·담당 범위·연락처. 퇴사는 감사·마지막 근무일·후임과 인계 정보. 회사 내부 사정·불만은 쓰지 않는다.
- **외부 문의 답변**: 문의 내용을 한 줄로 되짚고 답을 먼저. 답할 수 없는 부분은 담당 부서와 예상 회신일 안내. 약관·정책 근거는 조항을 인용한다.
- **공지 전달**: 원 공지의 핵심(무엇이·언제부터·우리가 할 일)을 3줄로 앞에 붙이고 원문은 아래에. 우리 팀에 해당하는 항목만 강조. 공지문 자체의 작성은 `announcement-writer-ko` 스킬이 담당한다.

## 변형 요청

- **메신저용 3줄 축약**: 첫 줄 `[목적]` + 핵심 한 문장, 둘째 줄 기한·형식, 셋째 줄 문의처 또는 다음 행동. 이모지 없이. 해요체는 사내에서만.
- **영문 병기**: 같은 구조로 영문을 아래에 붙인다. 한국식 겸양("부족하지만", "바쁘신 와중에")은 옮기지 않고 삭제한 이유를 한 줄 알린다. 직급은 사용자가 준 영문 직함, 없으면 이름만.
- **톤 조정**: "더 부드럽게"는 완충 문장 추가가 아니라 요청 문장을 의문형·선택형으로 바꾸는 것("가능하실까요?", "A/B 중 편하신 쪽으로"). "더 단호하게"는 기한과 미이행 시 조치를 명시하는 것. 어느 쪽이든 용건은 흐리지 않는다.
- **답장 작성**: 상대 메일을 주면 질문마다 번호를 붙여 하나씩 답하고, 못 답하는 항목은 예정일을 적는다. 상대 제목을 유지한다.
- **연속 메일 시리즈**: 요청 → 1차 독촉 → 2차 독촉를 한 번에 만들어 날짜만 바꿔 쓸 수 있게 한다. 각 단계의 발송 조건(요청 후 며칠)을 함께 적는다.

## 예시

**입력**: "고객사 A 박 과장님한테 견적서 회신 독촉 메일 좀. 지난주 화요일에 보냈는데 답이 없어. 이번 주 금요일까지는 받아야 해."

**판단**: 외부·실무자·1차 독촉 → 격식 톤. 오늘 2026-09-30(수) 기준 원 발송일 9/22(화), 기한 10/2(금).

**출력**:
```
제목: [한빛물산] 2차 견적서 검토 회신 요청 — 10/2(금)까지

박○○ 과장님, 안녕하십니까. ㈜한빛물산 영업1팀 김민수 대리입니다.

지난 9/22(화) 송부드린 2차 견적서(견적번호 HB-2026-0917) 검토 회신을 부탁드리고자 연락드립니다.
저희 10월 생산 일정 확정을 위해 10/2(금) 18:00까지 회신을 받을 수 있으면 감사하겠습니다.

- 검토 요청 사항: 단가·납기 조건 승인 여부
- 회신 방법: 이 메일에 회신 또는 견적서 서명본 첨부
- 필요하시면 견적서를 다시 보내드리겠습니다.

혹시 검토에 시간이 더 필요하시면 가능한 일정을 알려 주시면 그에 맞추겠습니다.
감사합니다.

김민수 드림
㈜한빛물산 영업1팀 대리 | 02-000-0000
```

**메신저용 3줄**:
```
[견적 회신 요청] 과장님, 9/22 보내드린 2차 견적서 검토 회신 부탁드립니다.
- 10/2(금) 18시까지 승인 여부 회신 요청드립니다 (10월 생산 일정 확정용)
- 일정이 어려우시면 가능한 날짜 알려 주시면 맞추겠습니다.
```

"답이 없어"를 상대 탓으로 쓰지 않고 우리 일정을 이유로 들었고, 견적번호·발송일을 넣어 상대가 메일함을 뒤지지 않게 했다. 견적번호는 사용자가 주지 않았으면 `[확인 필요: 견적번호]`로 둔다.

## 마무리 점검

- 제목만 보고 용건과 기한을 알 수 있는가?
- 첫 문단에 용건이 있는가? 배경이 먼저 오지 않았는가?
- 요청에 기한(날짜+요일+시간)·형식·담당이 있는가?
- 톤이 상대 직급·관계·사내외에 맞는가? 겸양 표현이 문단당 하나를 넘지 않는가?
- 독촉이면 원 요청일과 출구 문장이, 거절이면 대안이, 사과면 원인·조치·재발 방지가 있는가?
- 참조(CC)와 본문에 개인정보·기밀·타사 정보가 없는가?
- 과장·확언 표현("최고", "완벽", "반드시 가능")이 없는가?
